# R1 player preview: the frozen candidate and its qualification (#279)

**Status: RELEASE CANDIDATE with a published, bound image (#280).** The R1
bitstream is built, timing-closed, DSP-reviewed and bound to this candidate by
[`r1-2025.1.json`](r1-2025.1.json) (see "The R1 image" below). Its evidence is
digital (RTL simulation plus the routed implementation): no physical
programming, control or audio capture has been performed. **R0** is the published image
(`arty-a7-100t baseline 2025.1, r1`, contract revision 11, `a66c9349…`,
[RELEASE.md](RELEASE.md)); it stays untouched as the rollback. Nothing here is
evidence about R0, and R0's evidence is not evidence about R1.

### Supported quick-start

```text
.venv/bin/python fpga/uart_host.py --port /dev/cu.usbserial-XXXX run --note 45 --fixture none --image tree
.venv/bin/python fpga/uart_host.py --port /dev/cu.usbserial-XXXX run --preset m5a-saw --note 72 --fixture none --image tree
.venv/bin/python fpga/uart_host.py --port /dev/cu.usbserial-XXXX run --preset m5a-pulse --note 72 --fixture none --image tree
.venv/bin/python fpga/uart_host.py --port /dev/cu.usbserial-XXXX run --note 45 --fixture m5a --image tree
.venv/bin/python fpga/uart_host.py --port /dev/cu.usbserial-XXXX run --fixture demo --image tree
.venv/bin/python fpga/uart_host.py --port /dev/cu.usbserial-XXXX run --fixture bar808-full --image tree
.venv/bin/python fpga/midi_session.py --port /dev/ttyUSB1 --midi-in /dev/snd/midiC1D0 --image tree
```

**Removed from the R1 quick-start: `play --fixture m5a`.** It sends no patch
image, so what it plays depends on whatever the device held before, which
contradicts the known-state session start. `run --note 45 --fixture m5a` plays
the same phrase from the known state and is qualified on its own bytes below.
This also closes #255's M5A distinction for R1: the phrase's evidence is now a
replay of the CLI's captured bytes, not the bench-built `phrase` scenario.

### Supported domain

The R0 domain carries unchanged (`qualified_domain.py`): every programmed
increment in [2858, 4384395]; glides only from a known in-range increment;
`GLIDE_247` and `ROUTE_DRUMFILTER` refused; modulation excursion checked;
waveform sets as above; `PULSE2X` refused; a preset with a fixture refused.

and the playable range. **#247 stays open** and its restrictions stay in force.
The one R1 change is wording: `NOT_IN_IMAGE` for drift now says drift is
compiled into R1 but not qualified, instead of R0's "the image ignores it".

## Why the target is frozen apart from the sender (plan088)

`verify_rolling_playback.py` built its expectation from the same default
image the sender used. A revision-11 kit through revision-14 RTL compared with a
revision-11 expectation agrees perfectly and never plays the L2 clap. The
sender (`--image`) and the target (`--expect-image`) are now separate, the
target is never inferred, and before any RTL the executed setup bytes are
checked against the frozen target: preamble, the kit in order by digest, and
`ENV_FRATE[8]` = 68. Two controls must turn it red, and do:

- **wrong-kit-demo** (trial control): sender `--image release`, target frozen R1
  -> FAIL at the init bytes (preamble missing; kit differs at kit write 97,
  (96, 125960438) vs (96, 134152438); no `ENV_FRATE[8]`). Caught in 0.6 s, no RTL.
- **WRONG_KIT** (inside every R1 rolling run, both fixtures): sender
  `--image tree` with the release kit injected -> FAIL for the kit alone (the
  preamble is present). Caught.

R0's own checks are kept: `sim` mode of T-PLAY-DIGITAL is R0 bytes through the
current RTL, labelled a compatibility test, and T-RELEASE-BOUND still PASSes on
this branch (both stale controls caught).

### Headroom (#273's disposition, now on the production path)

The stress result stays as #273 recorded it (327 rail samples with every stop
at accent 2, against 324 pre-L2). The **nominal** mixes, decoded from the R1
wrapper's I2S above: `demo` peak **29,962** LSB, **0** samples at the rail
(+0.78 dB); `bar808-full` peak **19,517**, **0** at the rail (+4.50 dB). No gain
change is needed. **Unreconciled:** `tools/headroom_demo_mix.py` reported
pre-clamp peaks of 26,072 (demo, +1.99 dB) and 19,971 (bar808-full) on the
model. The RTL is bit-exact with the model driven by the UART-delivered
stimulus, so the difference lies in the stimulus, not in the RTL. *Which*
difference is an **unmeasured hypothesis**: the two stimuli differ in delivery
timing, in R1's known-state preamble, in the voice image and in the held
state. The production-path figure is the one that describes what a player
hears; the demo has 0.78 dB, not 1.99 dB, of headroom, and the L2 disposition
in `docs/scorecard/clap-l2/README.md` is marked accordingly.

### The default image: `release` (R0), and the one-line switch

This release keeps **`release` (R0) as the host default**; R1 is selected with
`--image tree`. The switch is one line, and the choice belongs to the operator:

```python
# fpga/uart_host.py
DEFAULT_IMAGE = "tree"      # was "release"
```

`fpga/midi_session.py` follows it. The switch is not silent, which is correct:
R0's manifest pins the bytes of its commands *without* `--image`, so
T-RELEASE-BOUND then REFUSES R0 ("held-note default: the replayed capture is
not what the CLI emits now"), and `r1-2025.1.json` goes STALE at
`host.default_image`. `test_r1_release.py` measures both. The PR that flips
the default must therefore also give R0's documented commands and manifest
captures an explicit `--image release`, and re-bind `r1-2025.1.json` with
`--write`.

### Found while building

- **The XDC's two UART-RX synchroniser constraints bind to nothing** (lines 42
  and 46, `.*g_uart/u_uart/rx_q_reg...`): Vivado names the generate-block
  instance `u_synth/g_uart.u_uart`, so both patterns match 0 objects
  (CRITICAL WARNING Common 17-55 / Vivado 12-4739, dropped). The SPI patterns
  match 6 and 3. The XDC is byte-identical to R0's, so R0 carries the same dead
  constraints. Effect on this image: none measured. `ASYNC_REG` is set on both
  `rx_q` flops by the RTL attribute (confirmed on the routed checkpoint), and
  `uart_rxd` has no input delay, so the path the false path would exclude is
  not timed either way. The publisher's `uart_gate_drift` checks the XDC text,
  not whether the constraint reached the design. Fixing it changes an input,
  so it is a new image, not part of this one.
- `tools/dsp_dpreg_extract.py` assumes it runs off the box and reaches it by
  ssh/scp; on the box itself (where Vivado is) that fails (no ssh to
  localhost). It was run through a two-line local-exec shim (`ssh r1-self CMD`
  -> `bash -c CMD`, `scp r1-self:A B` -> `cp A B`); the tool itself is
  unchanged and its hash checks all ran.
