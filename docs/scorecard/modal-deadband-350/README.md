# Modal-bank floor deadband through the shipped drum path (#350)

**Disposition: REFUSED.** The deadband is a real, confirmed production-path defect above the output stage's own
one-LSB floor. But no sound-facing limit for the persistent residual or for T20 error can be grounded in the
Fischer captures, so no external numeric repair target is recorded. The provisional arithmetic budget below is not
grounded, and it is labelled that way.

Measurement and target-setting only. No file under `model/`, `rtl-sketch/`, `fpga/` or any register image changed.

## What was measured

`tools/probes/modal_deadband.py` runs the **shipped** `DrumsFx` with its real kit image and its real coefficient
sequences (BD attack window, tom pitch drop). The bank is replaced by `TwinBank`, which is `ModalFx.step` verbatim
plus a float shadow of every mode. The shadow uses the same integer coefficients and the same post-numerator drive.

- Per render, the twin's int16 output is asserted bit-identical to `run_case.render_drum_solo` (`bank_is_stock`).
  This ran at accent 1.0 for every sound. A mutated render fails that check (`test_stock_check_is_not_vacuous`).
- The shipped configuration is asserted at point of use (`assert_production_config`): 28-bit state, Q15, CF 24,
  headroom 0, 19-bit body word, NUMS 11, 16 modes, 48 kHz, floor not round. Anything else REFUSES. Five wrong banks
  were tried and all refused.
- Residuals are read over the last 100 ms of a 2.2 s render. The departure is read only after the mode stops being
  driven and stops being retuned, so a pitch-drop or attack sequence is never read as a departure.
- The shipped kit does not write `A_COUPLE`, so `couple_en = 0`. The register's DC blocker is **not** in the path
  measured. Whether a host enables it is a deployment fact this record does not decide.

## The known answer (AC1)

`python3 tools/probes/modal_deadband.py --known-answer` reproduces `docs/scorecard/tom-body-334/deadband.json`
(left unchanged) at all four pings:

- the first >3.0 dB departure falls at the same 10 ms block (10 / 230 / 410 / 640 ms);
- the fixed tail peak is exact (2 / 3 / 7201 / 7201).

The float shadow is checked against the closed-form impulse response at 90 Hz/Q25, 56 Hz/Q22.3 and 2 kHz/Q10, so
it is not calibrated on our own recursion. The fixed recursion is checked against the same closed form while it is
far above the floor.

**Correction to the issue text.** The tails are not limit cycles. The exact classifier (`tail_shape`) shows the
2 and 3 LSB tails of the committed table are **stuck at -2 and -3**, a constant offset, and the "7,201" pedestal is
**-7,201**. The probe printed peak magnitude, so the sign was lost. `floor` rounds toward minus infinity, and the
pedestal is on the negative side or exactly zero for either ping polarity. A +100000 ping ends at -7201 and a
-100000 ping ends at 0 (`test_polarity_is_not_symmetric_under_floor_and_is_reported_signed`).

### Controls (properties x defects)

`python3 tools/probes/modal_deadband.py --controls`: all expected cells MOVED, `BLIND where it must MOVE: none`.
The five known-answer mutants are rounding, a float stub, a2+1 LSB, a wider state, and a recursion that never runs.
Each fails the intended `KnownAnswerMismatch`, not a crash. The twin-independence guard is blind to every mutant
except the float stub by design: it exists to catch a twin that is the fixed path. The five wrong-bank configs
are all refused by the config guard. The test file has 33 tests (`tools/probes/test_modal_deadband.py`).

**Honest limit on "start red".** The apparatus and its tests were committed together (`28cb433`). The red state is
demonstrated by the mutant matrix, which shows the stub and the wrong recursion failing. Git history does not show a
red-first commit.

## Result (all from `tables.md`)

The residual is a **standing negative pedestal** at the state, the bus and the int16 output. It is not a ring.
The table is the persistent int16 residual, the largest per voice.

| voice | max int16 residual | dBFS | state pedestal | fixed/float departure | T20 delta (fixed - float) |
|---|---:|---:|---|---|---|
| BD acc 0.25 / 0.5 / 1.0 / 2.0 | 36.0 LSB | -59.2 | -23,893 | 490-850 ms, float 28.5k-45k | +5.32 % at 1.0, +1.04 % at 2.0, REFUSED at 0.25 / 0.5 |
| LT | 15.75 | -66.4 | -7,029 to -7,201 | 520-630 ms, float ~5.3-5.5k | up to +9.87 % at 0.5 |
| MT | 9.0 | -71.2 | -3,127 to -3,201 | 360-400 ms | up to +9.43 % at 0.5 |
| HT | 7.65 | -72.6 | -1,702 to -1,704 | 290 ms | up to +5.35 % at 0.5 |
| SD low / high | 2.7 / 2.25 | -81.7 / -83.3 | -1,948 / -515 | 70-240 ms | up to +2.66 % at 1.0 |
| LC / MC / HC | 7.2 / 4.5 / 3.6 | -73.2 / -77.2 / -79.2 | -1,705 / -744 / 364 (one 370-sample cycle) | 220-590 ms | up to 3.9 % (MC at 0.5) |

- **Dev and confirmation agree.**
  - Rows above one int16 LSB: dev 12 of 18, confirm 12 of 36. Every voice shows a pedestal above 1 LSB in both
    tables.
  - Only 1 of the 36 confirmation rows is a limit cycle (HC at 1.5, period 370, state peak 364).
  - Congas end at exact zero more often than toms: the ring dies early, with the float still at 226-2,092 LSB.
- **The pedestal is not monotonic in accent.** BD is -23,893 at 0.25, 0.5, 1.0 and 2.0 but -3 at 0.75 and exactly 0
  at 1.5. LT, MT and HT flip between roughly 1,700-7,200 and 1-3 across accents. The five-accent BD set of #220 is
  a control for this, and it does not generalise to the other voices.
- **T20.** 5 of 48 voices are REFUSED by the scorer's own estimator. The record "ends before the decay does",
  because the stuck pedestal is itself what stops the backward integral from falling. They are the BD at 0.25 / 0.5
  / 1.5 and SD at 0.5 / 0.25 (BD 1.5 ends at exact zero).
  - A refusal is kept as a refusal, not filled in.
  - The measured deltas run up to 9.9 % dev and 3.9 % confirm.
- **Reconciliation with #220 / PR #543.** Taken from the issue's own account, not re-read:
  - Rounding does not fix the BD pedestal. The one-mode check agrees: round-half-up changes LT's stuck value from
    -7,201 to -3,599 and the departure from 410 to 530 ms, which is partial and not a fix.
  - The same arithmetic produces a pedestal on **every** modal voice, not only BD.
- **Distinct from #618.** The output stage's `>> 15` floor is not the recursion. The voice-level residual here is
  `fixed int16 - floor(float twin through the same output stage)`, so a 1-LSB output-stage bias cancels. The "float
  int16 peak 1" in `dev.json` is that floor acting on a near-zero float and is not a recursion effect.

## The target (AC4): what could and could not be grounded

**Provisional arithmetic budget (NOT externally grounded; for the follow-up to adopt or replace):** the persistent
residual of a mode should not exceed one int16 LSB at the output, the output stage's own granularity. In state LSB
that is `65536 * 32768 / (amp * 14746)`:

| mode | BD | SD low | SD high | LT | MT | HT | LC | MC | HC |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| state LSB | 671 | 832 | 251 | 462 | 359 | 224 | 238 | 181 | 108 |

Measured pedestals exceed this by up to 36x (BD) and 16x (LT). The derivation comes from the registers, not from
the measurement. For T20 there is no arithmetic budget to offer other than "do not be measurably different from the
float at the scorer's own estimator", which is a restatement and not a number.

**Sound-facing limits: REFUSED.** `ground.json` against the Fischer corpus (pinned `85fbecf`, clean tree, cloned
here, so the pin is verified by git and the sha256 manifest file is not present on this host):

1. **A DC / tail-floor limit cannot be read from the captures.** The `residual_dc.reference_gate` precondition (#152)
   REFUSES DC: the corpus has no `manifest.json` declaring `capture_coupling`. Every pedestal is DC, and a capture
   whose chain is AC-coupled or undeclared cannot show whether the machine has one.
2. **The captures that show their noise floor are at the same level as the pedestals, and AC only.** Valid
   100 ms tail floors, AC peak:

   | voice | LT | HT | HC | CP | CB | CY |
   |---|---:|---:|---:|---:|---:|---:|
   | dBFS | -70.5 | -73.0 | -72.7 | -69.1 | -75.4 | -73.7 |

   Our pedestals are -59 to -83 dBFS DC. The BD capture (1.5 s) is **still decaying at -55.9 dBFS** at its end, so
   it never reaches the level where the deadband acts (-57.6 dBFS at the BD departure). SD, OH, LC, MT and MC are
   still decaying too. CH, RS, CL and MA are under 300 ms.
3. **T20.** The only same-machine repeatability on record is the BD at DECAY position A, 1.30 %
   (`docs/bd-repeatability-measurement.md`). The shipped BD is DECAY 5.0 and the toms have none.
   - BD at 1.0 moves +5.32 %, above that spread. That is suggestive, but it is an extrapolation from a different
     setting and is not recorded as a limit.

**Named missing capabilities:**
- (a) a capture corpus manifest that declares coupling and DC response, or a DC-coupled capture;
- (b) a longer BD capture that actually reaches the deadband;
- (c) same-machine repeat captures of the toms at the shipped settings;
- (d) a qualified listening procedure for a steady sub-audible bus offset.

## Candidates, only enough to brief the follow-up (`candidates.json`)

No value is proposed and no sensitivity record is registered. A follow-up that proposes state fractional bits
(`state_q`), rounding, or anything numeric must register it under `tools/sensitivity.py` when it makes the proposal.

- **Rounding:** partial and not a fix (above).
- **State fractional bits.** The prediction was written down before the run (docstring of
  `modal_deadband_candidates.py`): the deadband sits at about `k/(1 - r)` state LSB independent of `state_q`, so it
  shrinks by 2^-dSQ when referred to the output. Measured at one pole each:
  - **Confirmed for the departure level.** LT stays at 5.2-7.2k state LSB across `state_q` 15, 17, 19, 21, with
    `k` about 1.2-1.7. The Q15-referred level is 6,261, 1,572, 447 and 82.
  - **Wrong for k at a BD-like pole.** Measured k is about 6, not order 1.
  - **The persistent value is not predicted by it.** At a BD-like pole (50 Hz, Q22.3) with `state_q` 21 the stuck
    value is -23,328 state LSB (about -365 Q15 LSB), against -6 at `state_q` 15. More fractional bits do **not**
    reliably shrink the pedestal. This needs a registered, swept record before it is recommended.

## Wrong-then-right count: 7

Six were caught by the controls before any production table existed. One was caught only after the tables, in the
candidates script. None changed a published production figure, because none existed yet.

1. The issue's "2-3 LSB limit cycle": the exact classifier shows a stuck negative offset (above).
2. My first twin-independence guard was BLIND to every mutant (it tested "a departure exists", which a float stub
   and a zero recursion both satisfy). Caught by the controls matrix and rewritten.
3. The closed-form agreement tolerance (1e-4) was wrong at 56 Hz. The floor drift is about 1.4e-3 of peak.
4. I expected a negative ping to leave a negative stuck value. It ends at exactly 0.
5. A late-retune test used a frame that landed in NO-TAIL, not REFUSED.
6. The first `modal_deadband_candidates.py` run compared `ModalFx`'s Q15 output word to a state-unit float, so every
   `state_q` > 15 "departed at 0 ms". Caught on reading the table, fixed by reading the state from `TwinBank`.
7. The prediction "k of order 1" held for LT and failed for the BD-like pole (k about 6).
